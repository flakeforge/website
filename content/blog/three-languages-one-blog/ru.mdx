Сайт FlakeForge доступен на английском, русском и узбекском. Интерфейс переведён полностью, а с постами сложнее: не всегда получается перевести текст до публикации. Нам нужна была схема, в которой пост выходит на одном языке, переводы добавляются позже, а ссылки при этом не ломаются.

## Одна папка на пост

Каждый пост лежит в отдельной папке, по одному MDX-файлу на язык:

```txt
content/blog/
  three-languages-one-blog/
    en.mdx
    ru.mdx
    uz.mdx
```

Английский файл обязателен, остальные по желанию. Имя папки становится адресом поста и одинаково для всех языков, поэтому при смене языка вы остаётесь на том же посте.

## Запасной вариант на английском

Если читатель открывает `/uz/blog/some-post`, а файла `uz.mdx` нет, страница показывает `en.mdx` и сообщает об этом сверху. Адрес работает, а остальная страница (навигация, даты, подписи) остаётся на узбекском.

Выбор файла помещается в одну небольшую функцию:

```ts title="src/shared/lib/content/files.ts"
export const resolveSourceLocale = (type, slug, locale) => {
  if (existsSync(join(CONTENT_ROOT, type, slug, `${locale}.mdx`))) return locale
  if (existsSync(join(CONTENT_ROOT, type, slug, 'en.mdx'))) return 'en'
  return null
}
```

## Чекбокс «Только на русском»

Запасной вариант сохраняет ссылки, но читателю, который выбрал русский, не всегда нужен список, наполовину состоящий из английских постов. На странице блога есть чекбокс с подписью на текущем языке: «Only English», «Только на русском» или «Faqat oʻzbekcha». Если его отметить, посты без перевода скрываются.

Фильтр работает в браузере поверх списка, который был отрисован при сборке, поэтому сама страница остаётся статической.

## Всё собирается заранее

Страница каждого поста существует для каждого языка уже на этапе сборки. `generateStaticParams` возвращает список адресов, а `dynamicParams = false` превращает любой другой адрес в 404 вместо рендера на сервере:

```ts
export const generateStaticParams = () => getPostSlugs().map(slug => ({ slug }))

export const dynamicParams = false
```

Frontmatter проходит через zod-схему во время сборки. Пост без заголовка или с неправильной датой ломает сборку и не попадает на сайт с пустым заголовком.
